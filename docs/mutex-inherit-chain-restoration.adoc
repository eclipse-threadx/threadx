== Root cause and invariants

`_tx_mutex_get` recorded a waiter's effective priority in the mutex and owner,
then `_tx_mutex_priority_chain` copied that number downstream. Its comparison
against an already equal/higher-priority owner both stopped boosts and broke cycles.
It had no withdrawal operation. `_tx_mutex_cleanup` only unlinked waiters.
With #807 alone, cleanup restores the first owner but does not refresh that owner's
outgoing mutex contribution or the next owner's effective priority.

The relevant state has distinct responsibilities:

[cols="1,3",options="header"]
|===
|Field |Meaning and update responsibility
|`tx_thread_user_priority` |Configured priority; thread-priority API owns changes. This is an independent recomputation seed.
|`tx_thread_priority` |Effective scheduling priority; the existing scheduler-specific priority functions maintain ready lists, execution selection, and thresholds. Within a visited cycle it is a result, not an independent seed.
|`tx_thread_inherit_priority` |Cached minimum donation across owned inheriting mutexes; `TX_MAX_PRIORITIES` means none. It must not seed its own cycle.
|`tx_mutex_highest_priority_waiting` |Cached minimum effective priority of waiters; it must be refreshed when membership or a waiter's priority changes.
|`tx_thread_owned_mutex_list` |Circular ownership list, including non-inheriting mutexes. Get/put own its links. Only inheriting mutexes contribute.
|Suspension list and count |Actual incoming dependency edges. Get, cleanup, put, and delete own membership. Recalculation never reorders or unlinks them.
|`tx_thread_state`, `tx_thread_suspend_cleanup`, `tx_thread_suspend_control_block` |Outgoing wait is usable only in an active mutex suspension. Chain discovery checks `TX_MUTEX_SUSP`, the exact `_tx_mutex_cleanup` function, non-null/valid mutex, inheritance, ownership count, and owner. Cleanup clears its marker before recalculation; transfer clears it before resuming the recipient.
|`tx_mutex_original_priority` |Acquisition-time bookkeeping, not a current priority contribution or restoration seed.
|===

The transfer regression exposed another SMP defect: `_tx_thread_priority_change`'s
inheritance fast path updated only user fields even when the effective priority
was still the old user priority. A recipient at base 5 with a remaining priority-10
waiter stayed at 5 after its base became 18. The fast path now additionally requires
that effective priority already equals inherited priority. Both suspended and
remotely executing ready owners exercise this correction.

== Recalculation and synchronization

`_tx_mutex_inherit_priority_update` is the common mutex entry point.
`_tx_mutex_priority_chain` owns recomputation for an owner, including release.
When chaining is disabled, the former scans the changed wait list and the latter
performs the original owned-mutex cache scan. The get path remains single-level.
No waiter-list prioritization is needed during recalculation; put retains its
existing prioritization before selecting a recipient.

With chaining enabled, the updater:

. Collects the first owner and at most K further waiting-mutex edges, stopping at an inactive/non-inheriting wait or repeated owner.
. Seeds scratch priorities from user priorities and waiters outside the collected path, ignoring effective-priority caches of all path members.
. Relaxes internal path edges in forward order twice. The first pass propagates tail seeds and can carry a minimum across a back edge; the second carries that minimum through the cycle. There is no recursive propagation or convergence retry loop.
. Refreshes all inheriting mutex caches and inherited-priority fields in the path from the solved values, then publishes effective changes once per owner through `_tx_mutex_priority_change`.

All observations and publication hold `TX_DISABLE` protection and preemption
disable. In SMP, this is the port's shared kernel protection, not just local
interrupt masking. Nested scheduler operations retain the outer protection;
no graph pointer is retained across an unlocked graph transaction. The original
single-core ready-list/threshold code and SMP ready-list, core mapping, rebalance,
and remote preemption code are retained. NI callers supply the same preemption
contract, and cleanup marks its unused NI suspension sequence explicitly.

Wait abort changes the departing thread's state before cleanup; termination also
sets a terminal state and prevents deletion during cleanup. Neither path is used
as an outgoing wait after detachment. Timeout restoration occurs before resume.
New ownership is linked and the recipient's cleanup marker cleared before either
owner is recomputed. Delete and termination release owned mutexes through put.

The optional `_tx_thread_mutex_priority_update` callback follows the existing
`_tx_thread_mutex_release` pattern: thread-only applications do not acquire a direct
link dependency on mutex services. Creation installs it and thread initialization
clears it. Thread-priority changes on active inheriting waits call it while protected,
including base changes inside a cycle whose initially cached effective priority
appears unchanged. Non-inheriting waits retain their FIFO behavior.

== Execution cost and limits

K counts mutex edges beyond the first owner, so at most N=K+1 distinct owners
are visited. Path collection/membership checks cost O(N*N); the two edge passes
cost at most 2N relaxations. Let M and W be total owned mutexes and waiters
across visited owners. Seeding and cache publication cost O(M + N*W).
At most N actual scheduler priority changes occur per owner update. A transfer
updates two roots (its recipient is no longer waiting). Existing put prioritization
and scheduler work are additional; K does not bound their work or dynamic list sizes.
There are no allocations, recursive calls, global graph scans, or new retry loops.

Graph processing holds interrupts/SMP protection and preemption disable for that
whole cost, including priority publication. Therefore K alone is not a constant
interrupt-latency bound: applications must bound mutex/waiter populations as well.
SMP incurs the corresponding shared protection hold time and existing scheduler
rebalance/IPI costs. No cycle-count or interrupt-latency measurement on hardware
was performed.

Scratch arrays use `(K+1)*(sizeof(TX_THREAD *) + 2*sizeof(UINT))`, plus fixed locals
and callee frames. GCC `-O2 -fstack-usage` measured the solver's own frame at K=2
as 128 bytes on RV64 GCC 13.2 and 112 bytes on the adapted SMP GCC 12 build
(144/128 bytes respectively with MISRA). These are function frames, not whole-call
stack bounds. The only new persistent storage is one optional function pointer
per kernel, 4 or 8 bytes according to the port. No public control-block layout changes.

Undefined chaining adds no graph arrays, discovery, or edge relaxation. Get keeps
its prior single-level work. Cleanup and waiter-priority changes add the necessary
direct restoration/update scan; put reuses its owned-cache calculation. Those scans
now hold protection to avoid inconsistent cache snapshots. Transfer also records
valid remaining contributions in the recipient's inherited cache.

A cycle fully inside the window loses obsolete external boosts. A cycle crossing
the configured boundary can feed a stale outside effective priority back into the
window; no claim of full restoration is made for that case. Likewise, owners beyond
the bound are not updated by an event. Applications needing full restoration must
configure K to cover their possible affected chains and cycles. Removing a donation
does not resolve a deadlock or make cycle members runnable.

== Suggested reviewer response

The issue was reproducible: with #807 alone, aborting H restored L1 to 20 but left
L2 at 5. The repair uses one inheritance updater for get, wait exit, configured
priority changes, and release/transfer. It recomputes a bounded owner path from
base priorities and valid outside donations before publishing priorities through
the existing single-core/SMP scheduler routines. Internal cached priorities are
excluded as seeds, which also removes self-sustaining boosts in contained cycles.
K continues to count edges beyond the first owner; cycles crossing that bound are
explicitly documented as a limitation. Regression tests cover timeout, abort,
termination, remaining donations, ownership transfer, priority changes, scheduling,
and a remotely executing SMP owner. The transfer tests also exposed and fixed the
SMP priority-change fast-path condition. Supported RV64 QEMU passes 99 tests;
adapted single-core/SMP mutex and configuration results, measured production
coverage, and all environment limitations are recorded above. Please retarget to
dev and run the supported Linux CI before merging.
